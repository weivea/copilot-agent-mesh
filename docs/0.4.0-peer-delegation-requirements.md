# Copilot Agent Mesh 0.4.0 需求文档：Peer Window Delegation

> 状态：需求草案（等待实现）<br>
> 日期：2026-08-30<br>
> 取代：0.3.0 的 Dashboard 驱动、前后端固定 DAG 的 Same-device Multi-project Collaboration<br>
> 技术依据：[Editor Agent Host Endpoint Spike](spikes/editor-agent-host.md)<br>
> 上游文档：[产品需求文档](../copilot-agent-mesh-prd.md)（0.1–0.3 部分仍然有效）

## 0. 为什么重写

0.3.0 交付的 Same-device Multi-project Collaboration 在真实使用中被证明**交互模型错误**：

1. 用户必须离开 Copilot Chat，切到 Dashboard，手动挑选两个 Workspace、指定
   frontend/backend 角色、填写目标，才能启动一次协作。
2. 编排是**写死的**：backend contract → backend implementation → frontend
   implementation → 双边验证。任何不符合前后端形状的需求都无法表达。
3. 中途需要输入时，用户要回到 Dashboard 点「Answer Input」，而不是在自己正在对话的
   Chat 里回答。
4. 用户真正想要的是：**在自己窗口的 Copilot 侧边栏正常对话，让 Copilot 自己决定把
   哪部分工作派给哪个窗口，并把结果拿回来接着说。**

这不是调参能修好的问题，是编排层和 UX 层的方向性错误。0.4.0 因此**替换**这两层。

### 0.1 保留的部分（不推翻）

下列 0.1–0.3 的成果全部保留，是 0.4.0 的地基：

| 能力 | 说明 |
| --- | --- |
| Device Broker | 同一 User Data 下 exactly one，generation-fenced，领导权接管 |
| Window Node | 每个普通 VS Code 窗口一个独立节点，心跳、注册、掉线检测 |
| Device → Node → Workspace 显式路由 | endpoint 只到实例粒度，这层路由仍是唯一的窗口寻址方式 |
| Workspace Lease | 一个 Workspace 同时只有一个 Writer |
| 本地认证 IPC | 同设备任务直连，不经过 Dev Tunnel |
| Task 生命周期与幂等 | `pending/running/needsInput/completed/failed/cancelled`、幂等启动标识 |
| AHP Runtime | 真实 `agentStarted → output → turnComplete/completed`、真实 cancel |
| 五个 Mesh Tools | `mesh_list_workers`、`mesh_delegate_task`、`mesh_get_task`、`mesh_cancel_task`、`mesh_answer_task` |
| 脱敏边界 | 绝对路径、Secret、Token、原始 Prompt/Output 不进入 Webview |
| Artifact Store | Broker 拥有、generation-fenced、不可变、仅结构化 JSON、严格上限 |

### 0.2 被替换的部分

| 被替换 | 替换为 |
| --- | --- |
| 固定 frontend/backend 角色与 DAG | 由父窗口 Copilot 自行决定的、按需的单跳委派 |
| Dashboard「Start Local Multi-project Collaboration」入口 | Copilot Chat 中的 Tool 调用 |
| `CollaborationRun` 聚合与依赖调度 | 普通 Task + 父任务归属信息 |
| `mesh_start_collaboration` / `mesh_get_collaboration` / `mesh_cancel_collaboration` | 复用既有五个 Task Tools |
| Dashboard 中的 Collaboration Runs 面板与 Answer Input 流程 | 节点选择、接收开关、窗口重命名、子任务只读状态 |
| 隔离 standalone Agent Host + 专用认证 Profile | 优先连接用户实例的 `editor` endpoint，复用用户身份 |

> **迁移策略：** 0.3.0 的 Collaboration 代码路径整体下线，不保留兼容层。已持久化的
> `collaborations/*.json` 在启动时被忽略并清理，不做数据迁移——0.3.0 是 Preview，
> 且从未在真实场景中成功完成一次运行。

## 1. 产品摘要

同一台设备上打开的每个普通 VS Code 窗口都是一个 **Mesh 节点**。用户在**任意一个窗口
的 Copilot 侧边栏正常对话**；当任务涉及另一个项目时，Copilot 通过 Mesh Tools 把子任务
派给用户**显式勾选授权**的对等窗口，那个窗口用它自己的 Workspace 上下文真实执行，完成
后把结构化结果交回发起方的同一轮对话。

没有中心协调者，没有固定角色。**每个窗口在自己这里都是主节点**，它勾选的其他窗口在这
次委派中充当子节点。同一个窗口可以在 A 的对话里当子节点，同时在自己的对话里当主节点。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| **Window Node** | 一个普通 VS Code 窗口中的扩展实例。`nodeInstanceId` 每次 Extension Host 重启都会变化。 |
| **Window Name** | 用户为「本窗口」设置的显示名。按 Workspace 稳定身份持久化，**仅用于显示与选择，绝不参与鉴权或路由**。 |
| **Peer Allowlist（对等白名单）** | 当前 Workspace 授权「我的 Copilot 可以看到并委派」的目标 Workspace 集合。**有方向**：A 勾选 B 不代表 B 勾选 A。 |
| **Accept Incoming（接收开关）** | 目标窗口自己的总开关，决定它是否愿意成为任何人的子节点。 |
| **Delegation（委派）** | 父窗口 Chat 中的一次 Tool 调用，在目标 Workspace 上启动一个真实 AHP 任务并等待其权威终态。 |
| **Child Task** | 被委派的任务。它是普通 Mesh Task，额外携带来源窗口信息，**不会被注入 Mesh Tools**。 |

### 2.1 双重授权门（Double Gate）

一次委派要成立，必须**同时**满足：

1. **目标侧**：目标窗口的 `Accept incoming tasks` 为开；
2. **来源侧**：来源 Workspace 的 Peer Allowlist 包含目标 Workspace。

任何一侧不满足：

- 该节点**不出现在** `mesh_list_workers` 的结果里；
- 即使 Copilot 直接指定其 ID，Broker 也必须**明确拒绝**，返回可区分的错误码，而不是
  返回一个 success-shaped 的空结果。

## 3. 目标

1. 用户不需要离开 Copilot 侧边栏就能完成跨项目协作。
2. 用户对「谁能看到我」「我能派给谁」有**显式、可审计、默认关闭**的控制。
3. 委派的结果在**同一轮对话**中返回，父 Copilot 可以直接基于结果继续推理。
4. 子任务在目标窗口**可见**，用户知道自己的项目正在被谁、以什么目标操作。
5. 全流程不经过 Dev Tunnel，不跨 Workspace 写文件，不重复执行。

## 4. 非目标

- **不做**跨设备委派（0.4.0 仅同设备；跨设备路径保持 0.2.0 的未验证状态）。
- **不做**多跳/递归委派（子任务不能再委派，见 FR-9）。
- **不做**任意文件传输（Artifact Store 仍只接受受限结构化 JSON）。
- **不做**多根 Workspace 节点（每个参与窗口恰好一个 claimed Workspace，见 FR-3）。
- **不做**接管或驱动目标窗口用户自己的 Chat 会话（稳定 API 不存在该能力，见 FR-8）。
- **不做** Windows / Linux / macOS x64 的 Worker Host 支持。
- **不向** Agent Prompt 注入 Git、branch、worktree、commit、push 或 PR 指令。

## 5. 核心用户流程

### 5.1 一次性配置（每个窗口各做一次）

1. 用户在窗口 B 打开 Mesh Dashboard，把 `This Window` 重命名为 `backend`。
2. 用户在 B 打开 `Accept incoming tasks`。
3. 用户在窗口 A 把 `This Window` 重命名为 `frontend`。
4. 用户在 A 的 `Local Window Nodes` 列表里勾选 `backend`。
5. A 的 Copilot 从此可以看到 `backend`；B 的 Copilot **看不到** `frontend`，除非 B 也
   自行勾选。

### 5.2 正常委派

1. 用户在 A 的 Copilot 侧边栏（Agent 模式）说：
   「后端加一个订单查询接口，然后前端这边把调用代码补上。」
2. Copilot 调用 `mesh_list_workers`，看到可用节点 `backend`。
3. Copilot 调用 `mesh_delegate_task`，目标 `backend`，说明目标与验收标准。
4. VS Code 弹出**一次**确认（Continue / Cancel），正文写明：目标窗口名、目标
   Workspace 名、任务摘要、以及**本次任务内**将自动批准的操作范围。
5. 用户点 Continue。
6. B 窗口出现该子任务：Dashboard 中显示为只读的 Incoming Task，同时（预期）在 B 的
   Chat Sessions 列表中出现一个带 Mesh 前缀标题的会话。
7. 子任务在 B 的 Workspace 中真实执行，期间的本地终端/文件确认按第 4 步授予的范围自动
   批准，不再打断用户。
8. 任务到达权威 `turnComplete/completed`，Tool 调用返回结构化结果。
9. A 的 Copilot 在**同一轮对话**里读到结果，继续写前端调用代码。

### 5.3 需要用户输入

子任务遇到**超出已授权范围**的问题（例如需要交互式认证）时：

1. 任务进入 `needsInput`；
2. **父窗口 A 的 Copilot** 通过 Tool 结果得知需要输入，直接在 A 的对话中向用户提问；
3. 用户在 A 的 Chat 里正常回答；
4. Copilot 调用 `mesh_answer_task` 把答案投递给该任务的精确 `inputId`；
5. 任务恢复 `running`。

> 用户**不需要**切到 B 窗口，也不需要打开 Dashboard 回答问题。这是对 0.3.0 最重要的
> 交互修正。

### 5.4 取消

- 用户在 A 停止当前 Chat Turn → Tool 的 `CancellationToken` 触发 → 精确取消该子任务 →
  等待权威 `cancelled/failed` → 释放 Workspace Lease。
- 用户也可以让 Copilot 调用 `mesh_cancel_task`，或在 B 的 Dashboard 上取消 Incoming
  Task（B 始终有权拒绝自己项目里的任务）。

## 6. 功能需求

### FR-1：窗口命名

1. 每个窗口只能重命名**自己**（`This Window`），不能重命名别人。
2. 名称按 **Workspace 稳定身份**（`createOpaqueWorkspaceIdentity` 产出的
   `sha256:<base64url>`）持久化，与 `nodeId`/`nodeInstanceId` 无关，重启后保留。
3. 名称在同一设备内**大小写不敏感唯一**；重复必须被拒绝并给出明确错误，不允许静默
   改名或加后缀。
4. 默认值为 Workspace 名；无法确定时回退为短节点 ID。
5. 名称长度有上限（复用 `PROTOCOL_LIMITS.nameBytes`）；必须拒绝包含路径分隔符、
   看起来像绝对路径、或匹配 Secret/Token 形状的输入。
6. 名称出现在：节点选择列表、`mesh_list_workers` 结果、任务来源/目标标识、子任务
   Session 标题。
7. 名称**仅用于显示与人类选择**。Broker 的鉴权与路由**只**使用 `workspaceIdentity`
   与 `nodeInstanceId`。伪造名称不得带来任何权限。

### FR-2：对等白名单

1. 白名单按**来源 Workspace 稳定身份**存储，条目是**目标 Workspace 稳定身份**。
2. 方向性：`A → [B, C]` 不隐含 `B → A`。
3. 运行时把条目重新绑定到当前在线的 `nodeInstanceId`；离线条目保留在配置中，在 UI 中
   显示为 `Offline`，不出现在 `mesh_list_workers` 结果里。
4. 条目数量有上限；超限拒绝新增。
5. 默认**空**。未勾选任何节点时，`mesh_list_workers` 返回空列表并附明确说明。
6. 白名单变更立即生效，不需要重载窗口。

### FR-3：接收开关与单 Workspace 约束

1. 每个窗口有独立的 `Accept incoming tasks` 开关，**默认关闭**。
2. 关闭时，该节点对所有来源不可见，且直接指定其 ID 的委派被 Broker 拒绝。
3. 0.4.0 要求参与委派的窗口**恰好 claim 一个 Workspace**。多根 Workspace 窗口可以
   作为来源，但不能作为目标，且必须在 UI 中明确说明原因。

### FR-4：Tool 表面

1. **复用**既有五个 Tool，不新增 collaboration 类 Tool：
   `mesh_list_workers`、`mesh_delegate_task`、`mesh_get_task`、`mesh_cancel_task`、
   `mesh_answer_task`。
2. **移除** `mesh_start_collaboration`、`mesh_get_collaboration`、
   `mesh_cancel_collaboration`（manifest 与 runtime 同时移除）。
3. `mesh_list_workers` 的结果必须体现双重授权门：只返回「目标已开启接收」且「本
   Workspace 已勾选」的在线节点，并给出窗口名、Workspace 名、能力标签、是否 busy。
4. `mesh_delegate_task` 语义从「立即返回 pending」改为 **在同一次调用内等待权威终态**
   （见 FR-5）。返回体必须**始终**包含 `taskId`，以便调用异常结束后仍可用
   `mesh_get_task` 追查。
5. 任何 Tool 的新增/修改必须同步：package manifest、runtime registration、input
   schema、token budget、错误码、文档、测试。manifest 与 runtime 的 parity 由测试断言。

### FR-5：长时委派与预算

1. `mesh_delegate_task` 的调用在子任务到达权威终态（`completed`/`failed`/`cancelled`）
   或需要输入（`needsInput`）之前保持挂起。
2. 预算通过既有输入字段 `timeoutMinutes` 表达：**默认 60 分钟**，上限从 0.3.0 的
   `1440` **收紧到 `60`**（调用现在会阻塞整轮对话）。超时后精确取消子任务，等待权威
   终态，返回带 `timedOut` 标记的结构化失败结果，**不得**把超时报告成 completed。
3. `CancellationToken` 触发时同样精确取消并等待权威终态，不留孤儿任务、Session、
   Lease、socket 或 timer。
4. 稳定 Tool API 未保证长时调用一定被 UI 支持（见 Spike 第 7 节）。因此必须保证：
   即使调用被宿主异常终止，任务本身仍可通过 `mesh_get_task` 查询、通过
   `mesh_cancel_task` 取消。

### FR-6：授权模型

1. 委派时在**父窗口**做**一次** `prepareInvocation` 确认。
2. VS Code 只提供 Continue / Cancel 两个按钮（见 Spike 第 7 节），因此授权范围必须
   **写在确认正文里**，而不是靠第三个按钮区分。
3. 确认正文必须包含：目标窗口名、目标 Workspace 名、任务摘要（有界）、以及将被自动
   批准的操作范围。
4. Continue 授予的范围**仅限本次子任务**：目标 Workspace 内的本地终端与文件操作。
   任务结束即失效。**不**按节点对、**不**跨任务、**不**持久化。
5. 以下**永远不自动批准**，必须升级为 `needsInput` 交由用户在父窗口回答：
   网络认证、跨 Workspace 写入、Secret 访问、对外发布类操作。

### FR-7：子任务隔离

1. 子任务在目标 Workspace 中执行，持有该 Workspace 的 Lease，保证同一 Workspace 同时
   只有一个 Writer。
2. 子任务**不得**写目标 Workspace 之外的任何路径。
3. 子任务的 Prompt **不得**包含 Git、branch、worktree、commit、push、PR 指令。
4. 子任务的 Prompt 与 Output **不得**回灌到 Webview；返回给父 Copilot 的是**结构化、
   有界、已脱敏**的结果。

### FR-8：目标窗口可见性

1. 目标窗口的 Dashboard 必须显示 Incoming Task：来源窗口名、任务摘要、状态、开始时间，
   以及一个取消按钮。
2. 扩展应把子任务创建为用户实例中的 AHP Session，标题带明确 Mesh 前缀与来源窗口名，
   使其**预期**出现在目标窗口的 Chat Sessions 列表中（依据 Spike 第 5 节）。
3. **不承诺**自动聚焦、自动打开，或把任务注入目标窗口用户**已有**的 Chat 会话——稳定
   API 不提供该能力。
4. 若 `editor` endpoint 不可用而回退到 standalone host，则第 2 点不成立，UI 必须**显式
   标注**当前处于降级模式。

### FR-9：禁止递归

1. 只有**用户发起**的窗口 Chat 才会被注入 Mesh Tools。
2. 由委派创建的子任务运行时**不注入** Mesh Tools，从根本上杜绝环路与 agent 树。
3. 若子任务仍以任何方式尝试委派，Broker 必须拒绝并记录明确错误码。

### FR-10：Agent Host 来源

1. 优先通过 `code agent endpoints` 发现当前实例的 `type: "editor"` endpoint，以
   Unix socket + WebSocket + `?tkn=` 连接，复用用户已登录的 Copilot 身份。
2. 发现失败或连接失败时回退到 0.3.0 的 standalone launcher，并在 UI 中显式降级提示。
3. `connectionToken`、socket 绝对路径、user-data 绝对路径**绝不**进入 Webview、日志、
   任务输出或错误消息。
4. user-data 目录必须按平台推导，不得硬编码。

### FR-11：Dashboard

保留并新增：

- `This Window`：窗口名 + 重命名入口 + 当前 Workspace 名 + claim 状态。
- `Accept incoming tasks`：开关 + 当前状态。
- `Local Window Nodes`：本设备其他节点列表，每项一个复选框（是否授权本窗口委派），
  显示窗口名、Workspace 名、在线/离线、是否开启接收、是否 busy。
- `Outgoing Tasks`：本窗口发起的子任务（只读状态 + 取消）。
- `Incoming Tasks`：其他窗口派给本窗口的子任务（只读状态 + 取消）。
- Agent Host 来源指示：`Editor`（正常）或 `Standalone (degraded)`。

移除：Collaboration Runs 面板、Start Local Multi-project Collaboration 入口、
Dashboard 侧的 Answer Input 流程。

**脱敏要求不变**：不向 Webview 发送绝对路径、Secret、Token、原始 Prompt 或原始 Output。

### FR-12：Preview 开关

整套能力由**默认关闭**的 Preview 开关控制。开关关闭时：Tools 不注册、节点不可见、
接收开关不可用。

## 7. 安全模型

| 威胁 | 缓解 |
| --- | --- |
| 未授权窗口被委派 | 双重授权门；不满足时节点不可见且直接寻址被拒 |
| 通过改名冒充其他窗口 | 名称只做显示；鉴权只认 `workspaceIdentity` |
| 子任务越权写入 | Workspace Lease + 只允许目标 Workspace 路径 |
| 授权范围蔓延 | 授权仅限单次任务，任务结束即失效；敏感类别永不自动批准 |
| Token/路径泄漏 | endpoint token、socket 路径、绝对路径纳入既有脱敏边界，测试断言 |
| 递归 agent 树 | 子任务不注入 Mesh Tools |
| 重复执行 | 幂等启动标识 + Broker generation fencing；重试、接管、重启都不得重复启动已接受任务 |

## 8. 验收标准

### AC-1：配置

- 两个真实普通 VS Code 窗口分别重命名成功，重启后名称保留。
- 重复名称被拒绝并有明确提示。
- 未开启接收开关的节点不出现在对方 `mesh_list_workers` 结果中；直接指定其 ID 被拒绝
  且错误码可区分。
- 取消勾选后目标立即从可见列表消失。

### AC-2：委派

- 用户仅在 A 的 Copilot 侧边栏对话，未打开 Dashboard，即完成一次跨窗口委派。
- 委派确认在 A 中出现且仅出现一次。
- 子任务在 B 的 Workspace 中真实执行，产生权威
  `agentStarted → output → turnComplete/completed`。
- Tool 在**同一轮对话**返回结构化结果，A 的 Copilot 基于该结果继续工作。
- B 的 Dashboard 显示该 Incoming Task。

### AC-3：输入

- 子任务进入 `needsInput` 时，用户**在 A 的 Chat 里**回答即可恢复执行。
- 答案绑定到精确 `inputId`；重复或过期的 `inputId` 被明确拒绝。

### AC-4：取消与失败

- 停止 A 的 Chat Turn 精确取消子任务，权威状态为 `cancelled`，Lease 释放。
- 60 分钟预算耗尽时精确取消并返回带 `timedOut` 的失败结果。
- 子任务失败时返回明确失败，不得被报告成 completed。
- 取消、超时、失败后无 Agent Host、VS Code、Socket、Timer 残留。

### AC-5：真实 E2E

默认关闭，例如 `MESH_PEER_DELEGATION_E2E=1 npm run test:peer-delegation-real`。
权威证据必须包含：

1. 两个普通 VS Code Window Nodes；
2. exactly one Broker；
3. 两个不同 Workspace Claims；
4. 双重授权门生效：未授权前不可见，授权后可见；
5. 委派确认被接受一次；
6. 子任务 `agentStarted/output/turnComplete/completed`；
7. 结果在父调用中返回，含 `taskId`；
8. 目标窗口出现 Incoming Task 记录；
9. Agent Host 来源为 `editor` endpoint（或显式记录降级）；
10. 本地路由未启动 Listener/Tunnel；
11. Workspace Lease 已释放，Profile Lock released；
12. 零 Agent Host、VS Code、Tunnel、Socket、Timer 残留。

真实 E2E **不允许** mock AHP、Fake Agent、把 `blocked`/`cancelled` 当 completed，或
放宽断言。

## 9. 测试要求

- 窗口重命名：持久化、大小写不敏感唯一、非法输入拒绝、长度上限、仅影响显示。
- 白名单：方向性、离线重绑定、上限、默认空、变更即时生效。
- 双重授权门：四种组合的可见性与直接寻址结果。
- Tool parity：manifest 与 runtime 完全一致；被移除的三个 Tool 不再注册。
- 长时委派：终态返回、`needsInput` 返回、超时精确取消、Token 取消精确取消。
- 授权范围：自动批准仅限本次任务；敏感类别升级为 `needsInput`。
- 递归防护：子任务无 Mesh Tools；子任务发起的委派被拒。
- Broker generation fencing 与接管恢复：不重复启动已接受任务。
- Workspace busy / Node loss / 单 Writer。
- Webview 脱敏：名称、路径、token、prompt、output。
- Agent Host 来源选择：editor 优先、失败回退、降级显式可见、token 不外泄。
- 所有资源幂等 Dispose。

每次提交前必须通过：

```sh
npm run check-types
npm run lint
npm run test:unit
npm run test:component
```

收尾还需运行：

```sh

```

## 10. 已知风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Copilot 不主动选择 Mesh Tools | 用户以为功能坏了 | 文档说明需在 Agent 模式启用 Tools；必要时用 `#` 显式引用；`mesh_list_workers` 描述写清触发场景 |
| 长时 Tool 调用被宿主中断 | 结果拿不回来 | 始终返回 `taskId`；任务独立于调用存活，可 `mesh_get_task` 查询 |
| 新建 Session 未出现在目标窗口 Sessions 列表 | FR-8.2 不成立 | 仅记为「预期」，由 E2E 判定；不成立时降级为 Dashboard-only 可见性并更新文档 |
| `editor` endpoint 不可用 | 失去身份复用与可见性 | 保留 standalone 回退并显式标注降级 |
| 目标 Workspace 同时被用户自己的 Copilot 编辑 | Mesh Lease 管不到用户自己的 Agent | 文档明确说明该限制；Incoming Task 可见，用户可随时取消 |
| 写入用户真实实例 | 误创建/残留会话 | 明确标题前缀、明确归属、终止即处置，并由残留断言覆盖 |
